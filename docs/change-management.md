# 変更管理

この文書は、変更をどの単位で提案し、どのように承認するかを定める。決定者と承認の成立条件は[`DEC-SYS-001`](meta/decisions/DEC-SYS-001-requirement-approval.md)で定める。

## ブランチとプルリクエストの単位

| 変更の種類     | 単位                                                                              |
| -------------- | --------------------------------------------------------------------------------- |
| 未決事項の解決 | 実装とは分けて切る。関連する複数の未決事項を1本にまとめてよい                     |
| 仕様と実装     | 同じ1本へまとめ、業務領域または機能の単位で切る                                   |
| それ以外       | 開発環境、設定、テンプレート、技術選定の記録など、関連する作業をまとめて1本にする |

1本のプルリクエストで扱う判断は、互いに関連し同時に取り消せる範囲に限る。

## 未決事項を解決する場合

`Q-*`の削除と、要件、仕様、`DEC-*`への反映を1本にまとめる。手順は[ドキュメント管理](documentation-management.md)の「未決事項を解決する」に従う。

複数の未決事項をまとめる場合は、1つの未決事項につき1つのコミットへ分け、どの決定がいつ成立したかを追えるようにする。

## 仕様と実装を変更する場合

仕様を先に書き、同じプルリクエストで実装する。要件TOMLの`status`は、このプルリクエストのマージで`accepted`になる。

## プルリクエスト

`.github/PULL_REQUEST_TEMPLATE.md`に従って記載する。文書を変更した場合は、[ドキュメント管理](documentation-management.md)の手動確認を実施する。
