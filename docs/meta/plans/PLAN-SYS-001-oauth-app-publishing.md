# PLAN-SYS-001 OAuthアプリの本番公開

## 目的と対象利用者

GoogleのOAuthアプリを「テスト」から「本番」へ移し、担当者のアカウントを事前登録しなくてもログインできるようにする計画である。

対象は担当者と開発担当者である。テスト状態では、`gm.ibaraki-ct.ac.jp`のアカウントであってもテストユーザーとして登録した利用者しかログインできない。当日に担当者が増えた場合、ロールの付与に加えてGoogle Cloudでの登録が必要になる。この二重の手間と、登録漏れによるログイン不能を無くす。

副次的に、来場者と担当者へ向けた個人情報の取り扱いの説明を公開する。

## 境界

含むもの。

- プライバシーポリシーページの作成と公開
- 利用規約ページの作成と公開
- Google Auth Platformのブランディング設定と、本番公開の申請
- ブランド確認(brand verification)への対応

含まないもの。

- 認証方式とロールの変更。[`DEC-SYS-002`](../decisions/DEC-SYS-002-staff-access.md)で定めた内容を変更しない
- 要求するスコープの追加。センシティブなスコープを加えると審査の対象となり、担当者へ警告画面が表示される
- `gm.ibaraki-ct.ac.jp`以外のアカウントの受け入れ

## 想定する体験

1. 担当者が自分の学校アカウントでログインする。事前の登録は不要である。
2. 同意画面にアプリ名が表示され、警告は表示されない。
3. ロールがNoneであるため、OwnerまたはAdminがロールを付与するまで公開ページだけを利用できる。

来場者と担当者は、公開ページからプライバシーポリシーと利用規約を読める。

## 実現可能性

要求するスコープは`openid`、`email`、`profile`の3つであり、いずれも非センシティブに分類される。センシティブまたは制限付きのスコープを要求しないため、スコープに対する審査は発生しない。

本番公開には次が必要である。

| 項目                   | 状態                                   |
| ---------------------- | -------------------------------------- |
| アプリ名               | 設定済み                               |
| ユーザーサポートメール | 設定済み                               |
| デベロッパーの連絡先   | 設定済み                               |
| 承認済みドメイン       | `nekomimi-ramen.com`を登録する         |
| ホームページ           | `https://nekomimi-ramen.com`。公開済み |
| プライバシーポリシー   | 未作成                                 |
| 利用規約               | 未作成                                 |
| ブランド確認           | 未実施                                 |

ホームページ、プライバシーポリシー、利用規約は、いずれも承認済みドメインの配下に置く必要がある。画面はすでにそのドメインで配信しているため、経路を追加して静的に配信できる。

保持する個人情報は、担当者のメールアドレスと表示名だけである([`SPEC-SYS-007`](../../specs/system-wide.md))。記述する対象が少ない。

## 要件にする前に決めること

- ブランド確認に要する期間。出店日までに完了しない場合の判断
- プライバシーポリシーに記載する保持期間と削除方法。[`Q-OPS-003`](../questions/Q-OPS-003-data-retention.md)の決定が前提になる
- 利用規約に記載する範囲。来場者は登録もログインもしないため、対象を担当者に限るかどうか
- 両ページの掲載場所と、公開ページからの導線
- 本番公開の後もテストユーザーの登録を残すかどうか。残す場合、ドメイン判定に加えた許可として働く
