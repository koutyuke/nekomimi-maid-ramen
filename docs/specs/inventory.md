# 在庫仕様

## 結論と対象範囲

在庫は商品の販売可否を判断する基準である。注文確定時に最新の在庫を確認し、注文の保存と在庫の減算を一体として扱う。

初期在庫の登録者、営業中の在庫修正、修正履歴、負数と上限の扱いは[`Q-INV-001`](../meta/questions/Q-INV-001-inventory-adjustment.md)で決定する。在庫不足時に会計担当者が行える変更は[`Q-SAL-002`](../meta/questions/Q-SAL-002-out-of-stock-change.md)、確定後の在庫復元は[`Q-SAL-003`](../meta/questions/Q-SAL-003-correction-cancellation-refund.md)で決定する。

## 管理データ

在庫は、商品、販売可能数、更新日時を持つ。注文確定処理と、許可された担当者だけが更新できる。手動修正は`Q-INV-001`、保持期間は[`Q-OPS-003`](../meta/questions/Q-OPS-003-data-retention.md)で決定する。

## SPEC-INV-001 在庫に基づく販売可否を表示する

関連要件: `REQ-INV-001`、`REQ-VIS-002`

来場者向けメニューと注文・会計画面は、現在の在庫に基づく販売可否を表示する。在庫がない商品は販売可能として表示しない。

### 受け入れ例

1. 在庫がある商品とない商品を用意する。
2. メニューと注文・会計画面を開く。
3. 両画面で販売可否が在庫と一致する。

## SPEC-INV-002 注文確定直前に在庫を再確認する

関連要件: `REQ-INV-002`、`REQ-SAL-005`

注文候補の表示時点ではなく、注文確定時点の在庫を最終判定に使う。いずれかの商品が不足する場合は、不足商品と確定できない理由を表示し、注文と在庫を変更しない。

### 受け入れ例

1. 注文候補を作成した後、別の注文によって対象商品の在庫を不足させる。
2. 元の注文候補を確定する。
3. 不足商品が表示され、注文件数と在庫が変化しない。

## SPEC-INV-003 注文保存と在庫減算を一体で行う

関連要件: `REQ-INV-003`、`REQ-SAL-005`、`REQ-SYS-002`

注文確定に成功した場合は、確定した数量だけ在庫を減らす。処理途中で失敗した場合は、注文だけが保存された状態や、注文がないまま在庫だけが減った状態を残さない。

複数の会計操作が同じ在庫を同時に確定しようとした場合も、在庫数を超える注文を成立させない。

### 受け入れ例

1. 注文確定処理の各段階で失敗を発生させる。
2. 処理結果を確認する。
3. 注文と在庫がともに更新されるか、ともに更新されていない状態になる。
4. 同じ在庫数を超える複数注文を同時に確定しても、確定数量の合計が在庫数を超えない。
