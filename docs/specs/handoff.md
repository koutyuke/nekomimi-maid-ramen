# 受け渡し仕様

## 結論と対象範囲

受け渡し担当者は、来場者が持つ紙の注文番号と完成した注文を照合して商品を渡し、注文を受け渡し済みに更新する。

## 画面と管理データ

受け渡し画面は、注文番号による検索、注文内容、完成状態、受け渡し状況を表示する。

注文番号は営業日ごとに1から始まる連番とし、注文が確定するたびに1ずつ増やす。翌営業日は1へ戻す。番号だけでは日をまたいで重複するため、データとしては営業日と番号の組で一意とする。

会計担当者が紙へ手書きし、受け渡し時に口頭で照合するため、桁数は小さいほうがよい。確定に失敗した注文には番号を発行せず、欠番も生じない。

## SPEC-HAND-001 完成注文を番号で照合する

関連要件: `REQ-HAND-001`、`REQ-KIT-002`

当日の注文番号から対象の完成注文と内容を確認できる。存在しない番号、未完成の注文、受け渡し済みの注文、取り消し済みの注文を区別する。

### 受け入れ例

1. 完成、未完成、受け渡し済み、取り消し済みの注文を用意する。
2. それぞれの注文番号を受け渡し画面で確認する。
3. 注文内容と現在の状態を区別して表示できる。
4. 発行していない番号では、該当する注文がないことが分かる。

## SPEC-HAND-002 受け渡しを一度だけ完了する

関連要件: `REQ-HAND-002`

受け渡し担当者は、完成した注文の商品と番号を照合して渡した後、注文を受け渡し済みに更新する。受け渡し済みの注文を通常の受け渡し操作で再度完了できない。

### 受け入れ例

1. 完成注文を注文番号で照合する。
2. 商品を渡して受け渡し済みに更新する。
3. 同じ注文番号で再度受け渡そうとする。
4. 受け渡し済みであることが分かり、二回目の完了操作は成立しない。
