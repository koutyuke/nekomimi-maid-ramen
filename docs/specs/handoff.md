# 受け渡し仕様

## 結論と対象範囲

受け渡し担当者は、当日の注文を受け渡しの優先順で確認し、ドリンクを準備する。全商品が完成した注文だけを紙の注文番号と照合して渡し、注文単位で受け渡し日時を記録する。

## 画面と一覧

Staff以上の担当者は、スタッフのトップから「受け渡し」を選び、`/handoff`を開く。画面は現在時刻から日本時間の営業日を自動で求め、その日の未取消注文だけを取得する。営業日と注文番号の入力欄は設けず、画面を開いたまま日本時間の0時を過ぎた場合は新しい営業日の一覧へ切り替える。

注文は1件ずつカードにし、画面幅に応じて1列または2列で表示する。カード上部には注文番号と、次のいずれかの状態を表示する。

| カードの状態 | 条件                                                 |
| ------------ | ---------------------------------------------------- |
| 受け渡し可能 | 未受け渡しで、全商品が完成している                   |
| 調理対応中   | 未受け渡しで、未調理または調理中の商品が一つ以上ある |
| 完了         | 受け渡し日時が記録されている                         |

商品行には商品名、数量、明細の調理状況を表示し、一つの枠内にまとめる。ドリンクの商品行には状態に応じた操作ボタンも同じ枠内へ表示する。mainとサイドの商品行は状態だけを表示し、更新操作を提供しない。

「完了を非表示」はチェックボックスとし、初期値をオンにする。チェック状態は保存せず、画面を開き直した場合はオンへ戻す。

注文カードは次の順に並べ、各区分内では注文番号の小さい順にする。

1. 受け渡し可能
2. 調理対応中で、未調理または調理中のドリンクが一つ以上ある
3. 調理対応中で、すべてのドリンクが完成している、またはドリンクがない
4. 完了

## 状態の管理

受け渡し状態は`orders.handed_off_at`だけで表す。`NULL`なら未受け渡し、日時があれば受け渡し済みである。調理状況の集計は[調理仕様](kitchen.md)に従う。

ドリンクはmainやサイドと同じ「未調理」「調理中」「完成」を使い、商品ごとに状態を更新する。受け渡し画面における商品分類ごとの更新制限は画面の操作制御とし、共通の状態更新APIはページ別に分けない。

全明細が完成した未受け渡し注文にだけ受け渡し操作を提供する。完了したカードには、ドリンクの状態更新操作も受け渡し操作も表示しない。

ドリンクの更新中は、送信開始から最新の一覧の再取得が終わるまで、その明細の操作と、その注文の受け渡し操作を無効にする。同じ明細への連打は送信せず、別明細の更新や別注文の受け渡しは継続できる。

注文番号は営業日ごとに1から始まる連番とし、注文が確定するたびに1ずつ増やす。翌営業日は1へ戻す。番号だけでは日をまたいで重複するため、データとしては営業日と番号の組で一意とする。営業日は日本時間の暦日である。

会計担当者が紙へ手書きし、受け渡し時に口頭で照合するため、桁数は小さいほうがよい。確定に失敗した注文には番号を発行せず、欠番も生じない。

調理と受け渡しの変更は自動で反映する。読み込み中、注文なし、取得失敗を区別する。WebSocketだけが切れた場合は「接続中」と表示し、操作を継続する。初回取得とHTTP取得・照合の失敗時は更新操作を止める。バックグラウンド再取得だけを理由に操作を止めない。同期と回復は[`SPEC-SYS-009`](system-wide.md#spec-sys-009-スタッフ画面を最新状態へ同期する)に従う。「注文情報を更新」でも現在の一覧を取得できる。

## SPEC-HAND-001 当日の注文を優先順に一覧表示する

関連要件: `REQ-HAND-001`、`REQ-KIT-002`

当日の未取消注文を1注文1カードで表示し、受け渡し可能、調理対応中、完了を区別する。別営業日の注文と取消済みの注文は表示しない。

### 受け入れ例

1. 当日と前日について、受け渡し可能、調理対応中、完了、取消済みの注文を用意する。
2. 受け渡し画面を開くと、当日の未取消注文だけが1注文1カード、1商品1枠で表示される。
3. 「完了を非表示」がオンになっており、完了した注文は表示されない。
4. 非表示をオフにすると、受け渡し可能、ドリンク未完成の調理対応中、ドリンク完成済みまたはドリンクなしの調理対応中、完了の順に並ぶ。
5. 各区分内では注文番号の小さい順に並ぶ。

## SPEC-HAND-003 ドリンクの調理状況を更新する

関連要件: `REQ-HAND-003`

受け渡し画面はドリンクの商品ごとに、未調理から調理中、調理中から完成、調理中から未調理への更新操作を提供する。完成から前の状態へは戻せず、未調理から完成へ飛ばせない。mainとサイドには状態を表示するだけで、更新操作を提供しない。

「完成」を押すと、注文番号・商品名・数量と、完成後は元に戻せないことを示す確認モーダルを開く。「はい、完成にする」で承認した場合だけ更新する。キャンセルや閉じる操作では変更しない。確認中に対象が調理中でなくなった場合や、注文が取消・受け渡し済みとなった場合は確認を閉じる。初回の読み込み中・取得失敗・対象明細の更新中・受け渡しの記録中は承認を止める。

### 受け入れ例

1. main、サイド、複数のドリンクを含む未受け渡し注文を用意する。
2. mainとサイドには調理状況だけが表示され、ドリンクには商品ごとの更新操作が表示される。
3. 一つのドリンクを調理中にして「完成」を押す。確認をキャンセルしても変更されず、再度開いて承認するとそのドリンクだけが完成する。
4. 調理中のドリンクを未調理へ戻せるが、完成から戻す操作と未調理から完成へ飛ばす操作は成立しない。
5. 受け渡し済みの注文には、どの商品にも更新操作が表示されない。

## SPEC-HAND-002 受け渡しを一度だけ完了する

関連要件: `REQ-HAND-002`

受け渡し担当者は、受け渡し可能なカードの商品と紙の注文番号を照合して渡した後、「受け渡し済みにする」を押す。確認モーダルには注文番号・全商品の名前と数量・未受け渡しには戻せないことを表示する。「はい、受け渡しを完了する」で承認した場合だけ更新し、キャンセルや閉じる操作では変更しない。確認中に受け渡し可能でなくなった場合は確認を閉じる。

サーバーは次の条件を一つの更新文で確認し、成立する場合だけサーバー時刻を`handed_off_at`へ保存する。

- 注文に明細があり、全明細が完成している。
- 注文が取り消されていない。
- 受け渡し日時が未記録である。
- 担当者が保存時点でもStaff以上の権限を持つ。

同時操作でも最初の1回だけ成功し、再送で日時を上書きしない。部分的な受け渡しは行わない。取消済みの注文と一部未完成の注文には受け渡し操作を提供しない。

初回の一覧取得中、HTTP取得・照合の失敗、対象注文の明細更新中、受け渡しの記録中は記録できない。競合や通信失敗では更新を自動再送せず、最新の注文を再取得する。結果が分からない場合は受け渡し済みか再確認し、商品を重ねて渡さない。

### 受け入れ例

1. 受け渡し可能な注文の商品と紙の注文番号を照合する。
2. 商品を渡して「受け渡し済みにする」を押す。確認をキャンセルしても記録されず、再度開いて承認した場合だけ受け渡し済みになる。
3. 同じ注文番号で再度受け渡そうとする。
4. 受け渡し済みであることが分かり、二回目の完了操作は成立しない。
5. 一部未完成、取消済み、明細なしの注文では受け渡しが成立しない。
6. 二端末から同時に記録すると一方だけが成功し、受け渡し日時が上書きされない。
7. 保存前に権限を失った担当者の操作は成立しない。

## API

| 操作                       | 経路                                                      |
| -------------------------- | --------------------------------------------------------- |
| 当日の注文と明細を取得する | `GET /staff/orders?businessDate=:businessDate`            |
| 明細の状態を更新する       | `PATCH /staff/orders/:id/lines/:menuItemId/cooking-state` |
| 受け渡しを記録する         | `POST /staff/orders/:id/handoff`                          |
| 注文の変更を照合する       | `GET /staff/orders/revision`                              |
| 変更を通知する             | `GET /staff/events`                                       |

一覧要求は日本時間の現在日を`businessDate`へ指定する。応答の各明細は、画面がドリンクの更新可否を判定できるよう商品分類を含む。記録の条件が成立しない場合は`409`を返し、成功時は受け渡し日時を返す。画面は変更通知を受けると、現在の営業日を指定して一覧を再取得する。
